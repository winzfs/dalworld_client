# DalWorld Client Current System Status

Last updated: 2026-05-21

이 문서는 현재 클라이언트 구현 상태를 빠르게 파악하기 위한 기준 문서다.
AI 작업자는 기능 추가나 수정 전에 이 문서를 확인하고, 실제 코드와 차이가 있으면 문서를 함께 갱신한다.

## 1. 프로젝트 개요

DalWorld 클라이언트는 Pixi.js v8 + TypeScript + Vite 기반의 2D 멀티플레이 생존/건설 게임 클라이언트다.

### 게임 개발 방향성

DalWorld는 **팰월드, 마인크래프트, 테라리아, 원스휴먼 계열의 생존 크래프팅 게임**을 지향한다.

핵심 방향은 다음과 같다.

- 오픈월드 생존, 채집, 제작, 건설, 전투, 탐험이 서로 연결되는 구조
- 플레이어가 자원을 모으고, 장비와 건축물을 만들고, 거점을 확장하는 장기 성장 루프
- 몬스터/펫/동료 수집과 전투, 생활 콘텐츠가 결합된 플레이 경험
- 샌드박스식 자유도와 목표 기반 진행이 함께 존재하는 구조
- 귀엽고 친근한 몬스터 생존/기지 건설 분위기
- 단순 전투 게임이 아니라 생활, 제작, 성장, 탐험, 협동이 누적되는 게임

단, 특정 게임을 그대로 복제하지 않는다.
위 작품들은 장르적 방향성과 시스템 조합의 참고 기준이며, DalWorld 고유의 2D 아이소메트릭 생존 크래프팅 게임으로 발전시키는 것을 목표로 한다.

클라이언트 기능을 추가할 때는 다음 관점을 우선한다.

- UI는 생존/제작/건설 루프를 빠르게 이해하고 조작할 수 있어야 한다.
- 인벤토리, 제작, 건설, 캐릭터, 지도, 몬스터 정보는 장기적으로 확장 가능한 구조로 만든다.
- 모바일 조작과 PC 조작을 모두 고려한다.
- 클라이언트는 표시, 입력, 미리보기, 로컬 예측을 담당하되 실제 판정은 서버 snapshot/event를 따른다.

### 제작 시스템 방향성

제작 UI는 생존 크래프팅 루프의 중심 UI다.

클라이언트 기준 제작 시스템은 다음 원칙을 따른다.

- 클라이언트는 제작법, 필요 재료, 필요 제작도구, 결과 아이템, 티어를 표시한다.
- 제작 버튼은 보유 재료와 제작도구 기준으로 가능 여부를 안내할 수 있지만, 제작 성공을 확정하지 않는다.
- 실제 제작 성공, 재료 차감, 결과 아이템 지급은 서버 응답 이후에만 반영한다.
- 제작법은 초반/중반/후반 티어로 표시되어 장기 성장 방향을 보여줘야 한다.
- 제작도구는 현재 인벤토리 보유 아이템으로 표시/검증되며, 향후 거점에 설치된 제작 시설 UI와 연결한다.
- 아이템 카탈로그와 제작 레시피는 서버 저장소와 반드시 동기화한다.

현재 제작 티어의 의도는 다음과 같다.

- 초반: 나무, 돌, 섬유 기반 생존 도구, 기초 무기, 작업대, 모닥불, 기초 포획구
- 중반: 광석 제련, 구리/철 장비, 고급 작업대, 연금 작업대, 정제 포획구
- 후반: 강철, 회로, 에너지 셀, 에너지 조립기, 고급 무기/도구, 엘리트 포획구

클라이언트는 다음을 담당한다.

- 화면 렌더링
- 입력 처리
- UI 표시
- 서버 요청 전송
- 서버 snapshot/event 반영
- 건설 미리보기
- 맵 에디터

실제 게임 판정은 서버가 담당한다.

## 7. 현재 구조상 주의점

### GameApp 책임 증가

`GameApp.ts`는 현재 많은 시스템을 조립하고, 건설 입력과 에디터 분기까지 포함한다.
새 기능을 추가할 때는 `GameApp.ts`에 직접 로직을 늘리기보다 별도 시스템으로 분리하는 것을 우선한다.

### 장르 방향성 유지

새 UI/시스템은 생존 크래프팅 루프에 기여해야 한다.
단기 기능을 추가하더라도 장기적으로 채집, 제작, 건설, 전투, 탐험, 몬스터/펫 성장과 연결될 수 있는 형태로 설계한다.

### 제작 UI 서버 권위 유지

제작 UI는 제작 가능 여부를 안내할 수 있지만 실제 제작 성공을 확정하지 않는다.
제작 성공, 재료 차감, 결과 아이템 지급은 서버 이벤트/스냅샷 이후에만 반영한다.
제작법이나 아이템 카탈로그를 수정할 때는 서버 저장소와 동기화해야 한다.

### 서버 권위 유지

클라이언트는 미리보기와 예측을 할 수 있지만, 실제 상태 확정은 서버 이벤트 이후에만 한다.

### 프로토콜 동기화

`src/protocol/messages.ts`는 서버 저장소와 맞아야 한다.
프로토콜 변경 시 양쪽 저장소를 같이 수정한다.
